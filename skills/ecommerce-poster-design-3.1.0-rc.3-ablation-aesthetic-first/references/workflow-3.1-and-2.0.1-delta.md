# 3.1.0-rc.3 完整工作流与 2.0.1 差异

## 完整工作流

1. 输入校验：确认商品图、商品名称/品类、卖点、价格促销、营销目标、画布与格式；建立八组保护内容。
2. P–M–S 分类与 C 库检索：证据不足的标签保持空值，按精确匹配到默认规则选择视觉参考并形成 style guide。
3. Logo 预检：SVG 为权威源时阻断活动内容和外部资源，栅格化为高清透明 PNG，记录源文件与派生文件哈希、尺寸和比例。
4. 生成计划：明确商品、品牌、文字、背景、布局和保护区域。ImageGen 只生成预留 Logo 区的底图，Logo 由确定性工具贴放。
5. 生成候选：产生新 version_id 与图片 SHA-256；工具失败且没有新图片时不计重绘次数。
6. 硬性合规：执行 HC-01～HC-12，保护商品、数量、Logo、价格、促销、卖点、CTA 和法务信息；失败则定向重绘并从硬检查重新开始。
7. 消费者 Agent：查看当前候选并提交 25 个子项观察，由脚本确定性计算五维与总分；要求总分≥80、五维各≥14、无硬失败、无锁定维度回退。
8. 美学 Agent：仅在消费者五维全锁后查看原图、360px 缩图、商品参考和任务；提交 25 个子项观察，由脚本计算六维与总分；要求总分≥80且六维分别达到下限。
9. 美学失败路由：根据未达标维度生成 `aesthetic-edit-lock/1.0`，只开放相应局部，冻结消费者功能、已通过美学维度和八组保护内容；返图重新执行完整链路。
10. 最终质量仲裁：在双 Agent 均通过后执行 `FINAL-QUALITY-3.1`，不新增分数；核验证据与画面，扫描可定位缺陷。可疑高分触发一次同图反向复核，不产生图片。
11. 强制缺陷路由：`TEXT_OVERLAP` 与 `LOGO_FLOATING` 至少为 moderate，不得降为 minor；生成 `final-quality-edit-lock/1.0`，默认局部重绘 1～2 次。
12. 返图回归：每张成功返图从 HC-01 开始，再跑消费者、美学和最终质量门；消费者任何锁定维度回退即淘汰返图并恢复最后通过基线。
13. 预算与交付：首版不计重绘，所有后续成功返图共用最多 8 次预算；同一候选全部通过才输出 passed，预算耗尽则只从硬合规和消费者通过的候选中选择最佳并输出 degraded；输入或图像不可评价则 blocked。

## 相较 2.0.1 的更新

| 能力 | 2.0.1 | 3.1.0-rc.3 |
|---|---|---|
| 评价链 | 硬合规 → 消费者 | 硬合规 → 消费者 → 美学 → 最终质量仲裁 |
| 美学评价 | 无独立专业美学门 | 25 子项、六维、确定性百分制与单维下限 |
| 双 Agent 通过后的处理 | 消费者通过即可进入交付 | 双 Agent Pass 仍只是上游建议，必须再过无分数最终质量门 |
| 高分防失真 | 无专门机制 | 分数异常饱和时对同一候选执行反向证据复核 |
| 美学返图范围 | 无美学编辑锁 | 只开放未达标维度，冻结五个消费者功能和八组保护内容 |
| 返图回退 | 重新检查，但无五维累计锁淘汰机制 | 任一消费者锁回退即淘汰返图并恢复基线 |
| Logo 管线 | 通用图片输入与生成 | SVG 安全预检、高清栅格化、预留区生成、确定性贴放及哈希证据 |
| 简单可见缺陷 | 没有最终缺陷分级路由 | 文字重叠和 Logo 悬空强制至少 moderate，必须局部重绘而非直接 Pass |
| 重绘合同 | 以硬合规/消费者建议为主 | 增加 `aesthetic-edit-lock/1.0` 与 `final-quality-edit-lock/1.0` |
| 版本绑定 | request/version 基础记录 | 同时绑定当前图片 SHA-256、上下文、上游结果和证据，旧报告随新候选失效 |

3.1.0-rc.3 仍继承 2.0.1 的 C 库、硬合规主体和消费者 Agent 1.5.3；新增能力位于主流程、美学模块接入、最终质量仲裁和 Logo 资产管线，不把生图权限下放给两个评价 Agent。
