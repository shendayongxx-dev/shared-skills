# 25项选档与证据

编号、名称和权重以assets/rubric.json为唯一配置。通用体验档位：0任务必需内容缺失或确认错误；1明显障碍；2部分满足；3清楚满足；4满足本子项明确增强条件。图像不可读或关键事实缺输入不是0档，按SKILL.md异常路由处理。每项写画面位置、可见内容及影响，不能仅写“很好”。没有实测不写“消费者3秒识别”或“提高转化”。选档时同时读取candidate-boundaries.md；相邻边界解释优先于笼统的“充分”“可靠”。

1/3等中间档必须依据相邻锚点解释；事实项不使用中间档掩盖已确认错误。hard_fail写critical_issues并与problem_list一致，由脚本阻止通过。程序核对结构和运算，不替代视觉事实判断。

非促销任务：D3_1至D3_4在对应输入字段为空、原Brief也明确不要求时可level=null，并写not_applicable_reason和evidence；脚本仅验证字段为空及理由，是否原Brief要求由模型核对。缺必需输入必须complete_input，不得用N/A绕过。D3_5仍评价任务所需信息到下一步的阅读顺序。适用权重重新归一至20，其余维度不允许N/A。

子项小数不取整；维度适用贡献归一后使用ROUND_HALF_UP，五维整数相加。明细记录配置版本、子项档位、权重、贡献、证据、原始维度分和整数分。P-M-S不改权重；每轮固定任务、标签及量表版本。升级至1.5.1后建立新评分轨道，旧结果保留为历史，不能假装量表版本相同。
